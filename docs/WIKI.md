## 1. 需求背景

一个人手工刷校招的失败模式不是「累」，是**漏**：岗位放出来那几天没刷到就没了。
所以产品的核心不是「聚合岗位列表」，而是**「哪些岗位新出现了」这条事件流**。

这决定了两个看起来奇怪的设计：为什么要存 `snapshots`（每轮原文都留，
不然漏报无法排查）、为什么误关闭比漏报关闭更严重（假 `job_closed` 直接
摧毁信任，而漏报只是晚知道一天）。

## 2. 关键决策

### 2.1 按 ATS 分层，不按公司分层

**决策**：适配器按招聘系统（feishu / moka / 北森）建，不按公司建。
**原因**：评审提的问题——中厂大多用第三方 ATS，同一 ATS 的租户前端是同一套应用。
实测证实：一个 `FeishuAdapter` 摊了 4 家公司，加一家的边际成本 = 配置里加一行。
**替代方案**：一家一个适配器。放弃原因是边际成本线性增长，且中厂数量远大于大厂。
**依据**：`docs/ATS_RESEARCH.md` 结论二。

### 2.2 代投闸门从提示词改成 API 形状

**决策**：提交必须带 `confirm_token`，拿不到 token 就调不到提交那一步。
**原因**：提示词约束的是倾向不是能力。不可逆动作不能靠模型记得住。
**替代方案**：提示词里写「请先向用户确认」。放弃原因见 `plans/001 §5`。

### 2.3 判不出的值写 `None`，绝不兜底

**决策**：`job_family` 判不出写 `None`，不写 `"other"`；`grad_year` 缺失走三态。
**原因**：「没有值」和「不匹配」混成一个分支，会静默丢岗位——用户永远不知道
它存在过。飞书上判不出族的比例高达 48.7%（nio），兜底成 `other` 等于
让一半岗位从按族筛里消失。
**依据**：`plans/002 §4`。

### 2.4 `--dry-run` 必须真的只读

**决策**：`db.register_source` / `start_run` / `finish_run` 都接 `commit` 参数。
**原因**：dry-run 靠 `conn.rollback()` 实现，而这两个函数原来无条件 commit，
commit 过的东西回滚不回来。表现是 `sync --dry-run` 往真库留下一行永远
`running` 的 run，而 `cli status` 取 `ORDER BY id DESC LIMIT 1`——于是一个
上一轮真实成功、有 795 条岗位的源，状态栏显示 `running` / 抓取 0。
**教训**：凡是「用来验证的东西」，它自己也得有测试。这个 bug 能活下来的
全部原因是 `dry_run` 在测试里一次都没被跑过。

### 2.5 校招门户按 `source_key` 分开，不合进租户

**决策**：`feishu:<tenant>:<portal>`，社招和校招各一个源。
**原因**：合在一起会让关闭判定的分母被混——校招门户整个下线（换届之间很正常）
时消失比例 627/2704=23%，低于 0.4 守卫，627 条会被静默关闭。分开之后是
100%，守卫必然触发。
**依据**：`plans/003 §6`。

## 3. 调研结论

### 3.1 仍然成立

| 结论 | 依据 |
|---|---|
| 厂商 API 对我们是关的，只能走租户公开前端 | `ATS_RESEARCH.md` 结论一 |
| 飞书接口免鉴权、`limit=500` 可用、深翻不重复 | `plans/002 §3` |

**这些错法归成一类，是「口径错」的第八种**（前七种在 `ATS_RESEARCH.md`）：
**把一个视图的性质当成数据源的性质。** 处方：拿到一批数据先问「这是哪一个池」，
再问「这批里有什么」。

`apply_url` 那条是第九种：**把上一个人的假设当成已核实的口径。**
处方：写进方案的每个 URL 形状，落地前打开过一次。

### 3.3 待查（不许当结论用）

- **「不带 `website-path` 那个池」是什么？** 三个池两两互不包含
  （nio: 2250 / 2077 交 1737；haidilao: 52 / 34 交 9）。已排除「每次调都不一样」
  （同一查询连打三次，id 集合三次全等）。**现在给它编解释就是编。**
- `website-path` 具体按什么校验（`code=-9000003` 的判定规则未知）。
- UA 门按 UA 的哪一部分判，未定位，也没拿真浏览器复核。
- Moka / 大易 / 北森的租户页格式没实测，现在写 `fetch()` 是凭想象。

## 4. 实验结果

### 4.1 `website-path` 全量翻页（2026-08-05）

12 个门户逐个翻到底，**每个都 `rows == count` 且 id 全 unique**：

| 租户 | 不带头 | index | campus/edu | 子门户 |
|---|---|---|---|---|
| nio | 2250 | 2077 | 627 | —— |
| xiaopeng | 1642 | 1659 | 436 | `398875`=335 |
| sensetime | 71 | 无 | 159（`edu`）| —— |
| haidilao | 52 | 34 | 无 | —— |

id 交集：校招 ∩ 社招 = **0**（三家全部组合）；`campus ∩ 398875` = **335**（全含）。

**2026-08-06 复跑的数**：sensetime `edu` 160、nio `index` 2078、
不带头 2249。数字自己在动（同一天内 nio 从 2250 变 2249），
**验接口正常要看 `code` 和门户是否存在，不看数字对不对得上**。

### 4.1b 找海底捞替补（2026-08-06）

海底捞没有校招门户，要换一家。三种探法只有一种管用：

| 探法 | 结果 |
|---|---|
| 猜租户 slug（18 个）| **16 个 `JSONDecodeError`**。和猜门户路径、猜 body 参数是同一种错法：猜命名空间 |
| 按域名 slug 认归属 | 早先就栽过（`luckin` 页面自称「加入狂浪俱乐部」）|
| **打开页面看它自称什么** | 管用。筛出 15 个真租户，其中 2 个有校招门户 |

留下 **`bytedance` 字节跳动**：campus **7395** 条，全量翻页 7395 unique id，
`{campus: 2048, intern: 5347}`，判不出族 416（**6%**，四家里最低 —— 标题最规范）。
备选 `chagee` 霸王茶姬 campus 只有 12 条，太薄，撑不起主场景。

### 4.1c `apply_url` 形状（2026-08-06）

| 形状 | 结果 |
|---|---|
| `/position/<id>` | **404，body 9 字节**（nio / xiaopeng / bytedance / sensetime 一致）|
| `/<portal>/position/<id>` | 200（192KB~879KB）|

**归属没验到，写在这儿免得下一个人以为验过了**：页面是客户端渲染的 SPA，
任何 id（含 `0` / `abc` / 19 位乱填数字）都回同一个 200 外壳，标题不在 HTML 里；
详情 XHR 没找到（15 个 JS bundle 里搜不到 `/api/v*`）。
所以「校招 id 必须配校招门户前缀」**只是按门户构造，没有独立验证** ——
200 只证明路由存在。要验得跑真浏览器看 network。

### 4.2 被排除的假设（记下来免得下一个人再试）

| 试过什么 | 结果 |
|---|---|
| `portal_type` / `portal_entrance`（query + body，值 1/2/6）| count 不变。真浏览器请求里有，但是陪跑的 |
| `process_type` / `job_process_type` / `website_id` / `portal_website_id` | count 不变 |

### 4.3 腾讯（`tencent_join`）的校招/实习构成

库内 801 条：`campus` 366 条全是 `grad_year=26`（上一届存量），
`intern` 435 条全是 `27`。**27 届秋招尚未开放**，所以用户看到「都是实习岗」是对的。

## 5. 问题复盘

各方案 §12 是权威版本，这里只放跨方案的模式：

| 模式 | 出现过几次 | 处方 |
|---|---|---|
| 拿一次采样的性质当接口的性质 | ≥8 | 计数带日期，区间带样本来源 |
| 把一个视图的性质当数据源的性质 | 1（这次）| 先问「这是哪个池」 |
| 两个键当成两批数据 | 1（这次）| 报数前算交集 |
| 改一半：只改了一侧的守卫 | 2 | 守卫改在哪一层，就在那一层再钉一次测试 |
| 用来验证的工具自己没被验证 | 1 | `--dry-run` 也要有测试 |
| §12 引用了不存在的测试 | 1 | 回填时把那条命令跑一遍 |
| **把上一个人的假设当成已核实的口径** | 1（`apply_url` 形状）| 方案里的每个 URL / 形状，落地前真打开一次。**表格排版会让假设看起来像已核实** |
| **猜命名空间**（门户路径 / body 参数 / 租户 slug）| 3 | 不猜，读页面说自己是什么 |
