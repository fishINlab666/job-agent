# 设计：云端为唯一采集真源，本机只同步、通知与兜底触发

> 编号 `022` · 日期 `2026-08` · 状态：已批准
> 目标：不再因 Mac 合盖、休眠或临时离线丢失招聘观察窗口，同时复用现有五源采集规则。

## 0. 已批准的产品决定

- 云端底座使用 Cloudflare Python Workers、Cron Triggers 与 D1。
- 云端是公开岗位采集的唯一真源；本机不得形成第二套采集事实。
- 每个工作日分三个弹性窗口：`08:00–12:00`、`12:00–17:00`、`17:00–22:00`
  （Asia/Shanghai）。每个窗口五个固定源全部成功才算完成。
- 本机联网/唤醒是兜底机会，不是“每次联网都重新采集”：云端已完成时只同步结果；
  云端有缺口时才请求云端立即补跑。
- 第一阶段只覆盖腾讯、蔚来、小鹏汽车、字节跳动、商汤科技，不新增公司，不做网页后台。
- 云端只保存公开岗位与采集运行事实；画像、简历、浏览器登录态、申请记录、真实投递永不上传。
- 用户已批准按本设计直接实施，不再为普通本地开发步骤拆分确认。

## 1. 用户问题与完成标准

### 1.1 用户问题

现有 LaunchAgent 依赖 Mac 在固定时间保持唤醒和联网。合盖休眠会错过任务；暗唤醒时
网络尚未恢复也会产生整轮失败。用户每天会有一至两次开机联网机会，但不能保证固定
分钟、持续供电或全天在线。

### 1.2 用户最终感受到的变化

```text
云端在早、午、晚窗口自动采集
  → 成功后保存公开岗位变化
  → 本机下次联网时只拉取新变化并发一条合并通知
  → 若云端某窗口仍缺失，本机请求云端立即补跑
  → 重复唤醒或重复请求不会产生重复批次、重复岗位或重复通知
```

### 1.3 第一阶段完成标准

1. 云端部署成功，五个固定源能完成一次真实采集。
2. 每窗口存在唯一记录；五源全部成功才进入 `complete`。
3. 任一源失败时窗口保持 `partial`，后续只重试失败源。
4. 本机能按游标增量同步，重复同步结果不变。
5. 本机只有在窗口有缺口时才触发云端补跑，重复触发不会重复执行已完成源。
6. 本机能展示当天三个窗口及五源状态，并对新增、变更、关闭岗位发送合并通知。
7. 云端数据扫描证明不含个人资料、申请或登录态字段。
8. 新的三个工作日产品观察从首个完整工作日开始；部署当天的即时采集只算技术试运行。

## 2. Module 与 Interface

### 2.1 共用采集核心 Module

现有 `RawJob`、飞书/腾讯响应解析、字段归一与岗位指纹规则继续作为唯一实现。网络请求
与持久化从规则中分离，调用者只需要知道：

```python
collect(source) -> SourceSnapshot
```

`SourceSnapshot` 包含源标识、采集时间、完整岗位清单、清单哈希及明确错误；禁止用空清单
代替网络失败。四家飞书仍共享同一个实现，腾讯保留独立解析，不复制规则到 TypeScript。

### 2.2 网络 Seam

- 本机 Adapter：现有同步 `httpx`。
- 云端 Adapter：Cloudflare Python Worker 支持的异步 `httpx`。
- 两者消费相同请求描述和相同纯解析函数；请求头、分页、源标识与空结果判据只定义一次。

### 2.3 持久化 Seam

- 本机 Adapter：现有 SQLite，用于画像匹配、通知和本机产品查询。
- 云端 Adapter：D1，只保存公开岗位、变化、窗口和同步游标。
- 本机通过只读同步 Interface 消费云端变化，不直接写云端岗位事实。

## 3. 云端运行模型

### 3.1 调度

Cron 每 30 分钟调用一次 Worker。Worker 用 Asia/Shanghai 判定当前工作日和窗口：

- 非工作日或窗口外：只返回状态，不采集。
- 窗口已 `complete`：幂等 no-op。
- 窗口未完成：领取窗口租约，只执行未成功的源。
- 同一窗口已有有效租约：当前调用退出，不并发采同一源。

工作日第一版按周一至周五计算，不自动推断中国法定调休；调休日历属于后续增强，不能
阻塞本次可靠性修复。

### 3.2 重试

- 单次源请求仅对 timeout、DNS/连接临时失败和 5xx 使用有限退避重试。
- 4xx、响应结构变化、分页不完整、源身份不一致立即失败，不用重试掩盖配置错误。
- 窗口内后续 Cron 只重试失败源；成功源的结果不可被较晚失败覆盖。
- 窗口结束后仍不完整时状态为 `missed`，保留所有原因，不冒充完成。

### 3.3 本机兜底触发

本机每 15 分钟在“机器已唤醒且网络可用”时执行轻量检查：

1. 查询云端当天状态。
2. 若当前或结束不超过 1 小时的窗口缺失，调用带鉴权的 `catch-up`；云端仍按租约、
   发布代次和来源最新窗口判重，过期任务不能覆盖新结果。
3. 若云端已完成，不触发采集，只拉取尚未同步的变化。
4. 检查失败不修改任何窗口事实，下次本机机会或下一次 Cron 再试。

这不是第二套调度真源：本机只能“敲门”，不能上传自行采集的岗位结果。

## 4. D1 数据模型

### 4.1 表

- `collection_windows`：工作日、窗口、状态、开始/完成时间、租约与最后错误。
- `source_runs`：窗口 × 源的每次尝试、状态、数量、清单哈希、错误分类与耗时。
- `cloud_jobs`：`source_key + external_id` 唯一的公开岗位当前版本及指纹。
- `job_changes`：递增游标、opened/updated/closed、公开岗位载荷、发生时间和来源 run。
- `sync_clients`：匿名客户端标识、最后确认游标和更新时间；不存用户资料。
- `source_heads`：每个来源最近获准发布的窗口/run，用于拒绝迟到旧任务覆盖新快照。
- `catch_up_gate`：全局补跑节流时间，不存用户或请求正文。

### 4.2 不变量

- `workday + window_key` 唯一。
- `window_id + source_key` 只能有一个成功事实；尝试可以多条但不可覆盖历史。
- `source_key + external_id` 唯一；同一指纹重复出现不产生变化事件。
- `job_changes.cursor` 单调递增；本机重复拉取和重复确认均幂等。
- 窗口租约带递增代次；租约过期或来源已有更新窗口时，旧 run 的所有发布写入归零并失败。
- 关闭岗位必须建立在该源完整、可信的本轮清单上；半截分页或异常空结果不得批量关闭。

### 4.3 数据保留

- 当前岗位与变化记录首期保留 90 天；窗口和 source run 保留 180 天。
- 清理只由独立维护任务按明确时间条件执行，不在采集事务中顺带删除。
- 第一版不上传现有本机历史数据库；云端从部署后的首轮建立新基线。

## 5. 云端 Interface 与安全

- `GET /v1/status/today`：返回三个窗口及五源状态。
- `GET /v1/changes?after={cursor}`：返回公开岗位变化和下一游标。
- `POST /v1/catch-up`：只请求云端补跑缺失窗口，不接受岗位数据。
- `POST /v1/clients/{client_id}/ack`：确认本机已处理到的游标。
- Cron 内部入口不暴露为公共写接口。

所有本机调用使用一个最小权限 bearer secret，secret 只存在 Cloudflare Secret 与本机私有
配置，不进入仓库、日志或数据库。接口校验方法、路径、内容类型和固定载荷；catch-up
有速率限制且服务端再次检查窗口状态。公开岗位数据虽然不敏感，写入口仍默认拒绝匿名调用。

## 6. 本机体验

- `jobagent cloud-status`：显示今天早/午/晚窗口、每源状态、最后同步时间和缺口原因。
- `jobagent cloud-sync`：幂等拉取变化、更新本机库、生成一条合并通知。
- `jobagent cloud-check`：供 LaunchAgent 调用；先 status，再按需 catch-up，最后 sync。
- 通知只汇总本次新应用的变化；重复游标、重复唤醒和失败重试不重复通知。
- 原固定 09:30/14:30/20:30 本机采集在云端验收通过后停用，迁移期间不得让两边同时
  写同一观察真值。

## 7. 错误与恢复

- D1 写入失败：该源 run 不成功，窗口不完成；不得只凭抓取返回值报成功。
- Worker 在抓取后中断：租约过期后可重跑；岗位和变化唯一键保证不会重复记账。
- 本机离线：云端继续采集；恢复联网后从上次游标续拉。
- 本机同步中断：未确认的游标可安全重放；通知在本地事务提交后才发送。
- Cloudflare 整个窗口不可用：记录 `missed`，本机恢复时请求 catch-up；若已越过当天
  22:00，只保留失败事实，不把次日数据回填成前一日成功。
- 招聘源结构变化：单源失败并显式展示；其余源可成功，但窗口保持 `partial`。

## 8. 测试与验收

### 8.1 自动测试

- 共用响应 fixture 同时验证本机与云端解析结果逐字段一致。
- D1 本地测试覆盖：窗口租约、五源聚合、失败源重试、岗位幂等、关闭守卫、游标重放。
- 本机测试覆盖：云端完整时不 catch-up、缺口时只触发一次、重复同步不重复通知。
- 安全测试覆盖：未鉴权写请求拒绝、catch-up 不接受岗位载荷、云端 schema 无个人字段。
- 所有测试使用 fixture/MockTransport/本地 D1，不访问真实招聘站，也不发送真实通知。

### 8.2 部署验收

1. 先部署测试环境，执行五源真实只读采集并对比现有本机解析数量与清单哈希。
2. 部署生产环境，触发一次即时技术采集并读回五源、窗口、岗位与变化计数。
3. 安装本机 cloud-check，验证云端完整时不会重新采集，能同步且不重复通知。
4. 停用旧固定本机采集任务，开始新的三个完整工作日观察。
5. 三日观察仍需独立官网证据确认；云端成功不能代替产品漏报/误报验收。

## 9. 明确不做

- 不做网页后台、多人账号、移动端或远程投递。
- 不把 profile、简历、申请、浏览器 session、cookie 或 secret 上传到 D1。
- 不新增公司、不改变岗位匹配和投递状态机。
- 不回填或篡改 2026-08-24 已失败的本机观察事实。
- 不把部署成功、首轮采集成功或演示成功称为“三工作日产品验收完成”。
