## 一、产品设计

### 1. 为什么现在做

不做的后果是**问一句话要贴一次日志**。

现在想知道「蔚来还有几个开放岗位」，动作是：我跑 `cli.py jobs --company 蔚来`、
把输出贴进对话、你读。中间那一步是纯人力搬运，而且搬运的是**已经在本地库里的数据**。
更糟的是它带着一个静默失效面：贴进来的输出是某个时刻的快照，
对话往下走几轮之后它已经过期了，但看起来和刚查的一样新。

第二个原因是**判据体检没有入口**。`checkup` 那套东西（投递表单的选择器还认不认
对方页面）只能在 CLI 里跑，而它的结论恰恰是对话里最该问的那类：
「现在能投吗」。代投卡在真登录上（Task #34/#35），但「判据还活着吗」这个问题
不需要登录也该能问。

第三个原因，也是决定**边界画在哪**的那个：这一层最大的风险不是查不到，
是**代投混进来**。`execute()` 提交之后对方系统里那条记录撤不回来，
而闸门的全部价值在「人看过字段清单再点头」。把 `prepare`/`execute` 做成 MCP 工具，
等于把这个闸门交给一个会自己决定要不要调工具的东西。这条不做出决定，
整个 MCP 层就不该存在。

### 2. 用户会看到什么

```
用户在对话里问「蔚来还有几个开放岗位」
  → 模型调 list_jobs(company="蔚来")
  → 屏幕上出现实时条数 + 前 30 条，不用等我跑命令贴日志
```

```
用户问「现在能投字节那个岗位吗」
  → 模型调 check_form_selectors(external_id=..., user_data_dir=...)
  → 屏幕上出现逐条判据的绿/红，以及「哪几条这次证明不了」
```

要能一眼看出**「查不到」和「没有」的区别**，这两件事的处置完全不同：

```
list_sources 里 last_run 为 null   → 这个源一次都没跑过，去 sync
list_sources 里 status = failed    → 跑过但失败了，去查错
```

反面例子（这一层刻意做不到的）：

```
用户在对话里说「帮我投这个岗位」
  → 没有这个工具。模型只能告诉你去命令行跑 jobagent prepare
```

## 二、具体实现

### 4. 数据长什么样，空值怎么办

这一层不写库，所以「空值」问的是**返回值里的空怎么表达**。
关键是每一处空都要能被区分成「没有」还是「查不出来」：

| 字段 | 有值时 | 取不到时 | 「没有值」和「不匹配」分开了吗 |
|---|---|---|---|
| `job_family` | tech / product / … | `None`（判不出族） | **是** —— 判不出族的岗位按任何族筛都查不到它，**包括 other**。工具 docstring 明写这一句，否则「按 other 筛」会被当成兜底 |
| `explain_match.state` | `hit` / `miss` | `unknown` + `missing` 列出缺哪几维 | **是** —— 三态，不是布尔。`unknown` 是「信息不全，既没被排除也没被确认」，要人看一眼，不是不合格 |
| `list_sources.last_run` | 最近一次采集 | `None` = **一次都没跑过** | **是** —— 和「跑过但失败了」（`status=failed`）分成两种。前者去 sync，后者去查错 |
| `apply_limit` / `apply_remaining` | 数字 | `None` = 没设上限 | **是** —— 不是 0。判成 0 的话「没设上限」会被读成「配额用完了」 |
| `runs.finished_at` | ISO 时间 | `None` = 这轮没收尾（进程被杀或正在跑） | **是** —— 这条痕迹是故意留的，不是数据缺失 |
| `events.payload` | dict | 解不开时给 `payload_raw` | **是** —— 那是数据问题，不是「这次没有变动」 |
| `list_jobs.notes` | 给人看的提醒 | `[]` | 有内容就该转述（例如 `allow_missing` 没生效） |
| `_intent()` | profile 里的 intent | `{}`（档案不存在） | 匹配退化成「什么都不排除」，不是整个工具挂掉 |

`total` 和 `returned` 是两个数，**`total` 不受 limit 影响**：
混了就会把「返回 30 条」说成「只有 30 条」。钉住它的是
`test_total_is_not_capped_by_limit`。

### 5. 硬约束在哪一行

这一层的全部价值在于**它做不到的事**。所以三条约束都必须是形状上的，
不是 docstring 里的请求。

**① 注册表里没有写动词 —— 主约束。**
`prepare` / `execute` / `submit` / `apply` / `sync` 一个都不注册。
模型调不到不存在的工具。守它的不是「我记得没注册」，是
[test_no_write_verb_is_registered](tests/test_mcp_server.py:105)：
**遍历真实注册表**比对 `WRITE_VERBS`，将来谁手滑加一个 `@mcp.tool()` 的写动词，那条会红。

管的是**头动词**不是子串：

```python
READ_VERBS  = {"list", "get", "explain", "count", "search", "check"}
WRITE_VERBS = {"prepare", "execute", "submit", "apply", "confirm", "discard",
               "sync", "init", "repair", "delete", "update", "insert", "write",
               "create", "remove", "set", "refresh", "add", "mark", "run"}
NOUN_PHRASE_TOOLS = frozenset({"job_changes"})   # 例外列出来，不是把规则放松
```

为什么管头词：`list_sync_runs` 读的是采集历史，名字里有 sync 但它不采集。
按「出现即禁」会把它拦下来，逼人把守卫放松成子串匹配之类 —— **那才是真的把门拆了**。
反过来正面清单漏的方向是「新工具名不在清单里就红」，需要人答一句
「它是只读的吗」，这个方向是安全的。

**② 连接是 `mode=ro`。** `db.connect_readonly()`。这条是兜底，管的是
「我在工具体里写错一句 SQL」——SQLite 自己拒绝，不靠我记得。

**③ 事件种类是白名单，不是黑名单。**

```python
JOB_EVENT_KINDS = frozenset({
    "job_opened", "job_closed", "job_updated", "source_bootstrapped",
})
```

同一张 `events` 表里还躺着代投侧的事件，它们的 payload 里有 `screenshots/` 路径 ——
那些截图是**填好的表单，画面上有姓名手机身份证**。而代投侧的 kind 是
`f"apply_{result.status}"` **拼出来的，grep 数不出全集**：将来多一个状态
就多一个漏出去的 kind。黑名单在这种形状下一定会漏；白名单漏的方向是
「少给一类事件」，看得见。

**④ 只有 `intent` 过边界，而且是白名单挑键。**
`_intent()` 是这一层**唯一**读 `profile.yaml` 的地方。
第一版写的是「只取 `intent` 这一段」，红队验出来**这条当时是假的**：
把它改成 `return match.load_profile()`（整份 profile 往下传），
哨兵测试**照样全绿** —— 因为 `match.classify` 只读它认识的那几个键，
身份数据传进去了但没被用到、于是没出现在返回值里。

也就是说「只有 intent 过边界」靠的是**下游恰好不读**，不是这一层真的挡住了。
下游哪天多读一个键，这条就静默失效，而失效的表现是**身份数据出现在对话里**。
改成 `INTENT_KEYS` 白名单之后，断言放在「交出去那一刻」而不是「下游用不用」。

**⑤ `execute` 留在 CLI，`SESSIONS` 压根不碰。** 这不是「暂时不做」，
见 §8 第一条。

### 6. 判据的粒度

**「这个工具是读还是写」的判据是「头一个词」，不是「名字里有没有」。**
差一级的后果在 §5 ① 写了：按子串判会把 `list_sync_runs` 误伤，
而被误伤一次就会有人去放松守卫。

**「这条判据还活着吗」的判据分两级，不能混。**
`check_form_selectors` 返回的 `all_valid=true` **不等于**「站点没改过文案」：
有些判据只在异常页面上才触发（岗位已关闭、提交成功、重复投递），
拿一个正常岗位页核不动它们。所以返回值里 `unprovable` 单列一栏 ——
这一级是「这次证明不了」，和「验过了是好的」不是同一件事。
转述时要一起说，只说「全部有效」就是把 `unprovable` 那几条洗成了绿的。

**「走不到表单」和「判据坏了」是两级。** 没有登录态时会走到登录墙，
那时 `checkup` 只返回一行 blocker（不是一片假红），`reached_form=false`。
混成一级的后果是每次没登录都满屏红，人开始忽略这个工具。

### 7. 数字的口径

| 这个数 | 分子数的是什么 | 分母数的是什么 | 会不会随时间动 |
|---|---|---|---|
| `list_jobs.total` | 筛完的**全量**条数 | — | 会（采集在动） |
| `list_jobs.returned` | 实际返回的条数（`min(total, limit)`） | — | 会 |
| `apply_remaining` | 该公司剩余配额 | 该公司 `apply_limit` | 会（投一次少一个） |
| `job_changes` 的 limit | **合并重排后**的最近 N 条 | — | 会 |

三条口径提醒：

- **`total` 不受 `limit` 影响。** 混了就会把「返回 30 条」说成「只有 30 条」。
- **`job_changes` 的 limit 是「最近 N 条」，不是「每种最近 N 条」。**
  各 kind 分别取了 limit 条，合起来必须重新排序再截断 ——
  不重排的话条数对，但**不是最近的那些**。
- **配额按公司算，不按源算。** 同一家公司多行源时用量是合起来的。

### 8. 这次明确不做什么

- **不做代投工具。** `prepare` / `execute` 不注册，`SESSIONS` 这一层不碰。
  理由不是「以后再说」：`execute()` 提交之后对方系统里那条记录**撤不回来**，
  闸门的价值全在「人看过字段清单再点头」。做成工具就是把闸门交给一个
  会自己决定要不要调工具的东西。这是硬边界，不是排期问题。
- **不做投递记录查询。** `applications` 不在这一层。那里有投过哪些岗位、
  截图路径、脱敏后的字段值 —— 都不该为了「方便问一句」而进对话。
  要看去 `jobagent applications`。
- **不做 `health` 巡检工具**（plan 013）。它要开浏览器、跑 7 分钟、
  且会对外发几十个请求。只读层的边界是「不对外」，
  唯一的例外是 `check_form_selectors`，而它 docstring 里带了成本警告
  （`test_the_docstring_warns_about_the_cost` 钉住这句话必须在）。
- **不开 HTTP 传输。** 只走 stdio。一个本地库不需要监听端口，端口就是攻击面。
- **不缓存连接成模块级单例。** sqlite3 连接默认绑在创建它的线程上，
  而 MCP 的工具调用不保证同线程。开连接对本地 SQLite 是微秒级的事。
- **不做写库的「便利工具」**（比如「顺手标一下这条已关闭」）。
  一旦有一个写动词，`WRITE_VERBS` 那条守卫就得开例外，
  而例外一开就没有形状约束了，只剩我记不记得。

## 四、复盘

### 11. 方案和实现差在哪

**① 这份方案是回填的，顺序违反了父仓库那条唯一的硬规则。**
`../CLAUDE.md` 写的是 **方案 → 代码**，而这里是三个 commit 落地之后才写方案。
按那份规则，MCP 只读层完全落在「需要方案」那一栏 ——
它加了一个模块的行为、引入了一个新的执行边界（对话能不能碰库）。

代价不是抽象的。**代码写完了、47 条测试全绿、而 `mcpServers` 是空的** ——
也就是说这套东西一次都没被真正调用过。方案 §2「用户会看到什么」如果动手前写过，
第一句就会是「用户在对话里问……」，而那句话逼出的第一个问题是
「客户端怎么知道有这个 server」。没写，于是做完了没人用。

**② 「只有 intent 过边界」第一版是假的，红队才验出来。**
第一版 `_intent()` 只是 `load_profile().get("intent")`，看起来对。
把它改成整份 profile 往下传 —— **哨兵测试照样全绿**，因为 `match.classify`
只读它认识的键，身份数据传进去了但没被用到。

这条约束当时靠的是**下游恰好不读**，不是这一层挡住了。已改成 `INTENT_KEYS`
白名单：断言放在「交出去那一刻」，不是「下游用不用」。

**③ 守卫从「名字里不许有写动词」改成「头动词白名单」。**
第一版按子串禁，`list_sync_runs` 当场被误伤（读采集历史，名字里有 sync）。
误伤一次就会有人去放松守卫成子串匹配之类，而那才是真的把门拆了。
改成正面清单 + `NOUN_PHRASE_TOOLS` 例外**列出来**。

**④ `sync_history` 这个名字被守卫当场拦下，这是守卫第一次真的干活。**
读的东西名字却以写动词开头 —— 模型看名字判断不了它会不会触发采集。
改名 `list_sync_runs`。

**⑤ `check_form_selectors` 的 headless 默认值和 CLI 相反。**
CLI 那边是 `False` 因为确认环节要人看着页面；这里没人看着屏幕，
弹一个看不见的窗口只是白占资源。这条差异容易被「统一一下默认值」抹掉，
所以有一条专门的测试钉它。

**⑥ “server 能工作”不等于“客户端已经接入”。** 历史上 stdio 探针能返回真数据，
但客户端没有读取对应配置；验收必须看客户端运行时注册表和真实工具调用，不能拿
server 自测替客户端签字。

**⑦ “配置文件里有 JSON”不等于“App 读了这个文件”。** 2026-08-13 的
Desktop 配置写进了 `Claude/`，实际发行版读取 `Claude-3p/`，所以从未生效。
这个事实只作为历史教训；当前五工具恢复接入时必须重新授权并做运行时读回。

### 12. 实现中踩到的坑

- **现象**：把 `_intent()` 换成整份 profile 往下传，身份哨兵测试全绿。
  **原因**：断言放在「返回值里有没有出现哨兵串」，而下游只读它认识的键，
  所以传过去的身份数据没被用到、也就没出现在输出里。
  **修法**：`INTENT_KEYS` 白名单，在交出去那一刻挑键。
  **钉住它的测试**：`test_intent_helper_hands_over_only_whitelisted_keys`
  + `test_an_unknown_intent_key_is_not_handed_over`

- **现象**：`job_changes(limit=10)` 返回 10 条，但不是最近的 10 条。
  **原因**：四个 kind 各取 10 条再拼起来，没重排就截断。
  **修法**：合并后按 `(occurred_at, id)` 倒排再切。
  **钉住它的测试**：`test_limit_means_the_most_recent_overall`

- **现象**：工具名守卫把 `list_sync_runs` 判成写工具。
  **原因**：按「名字里出现写动词」判，`sync` 是子串。
  **修法**：改判**头动词**，配 `READ_VERBS` 正面清单。
  **钉住它的测试**：`test_the_verb_lists_do_not_overlap`
  + `test_the_guard_would_catch_a_write_tool`

- **现象**：`all_valid=true` 被读成「站点没改过文案」。
  **原因**：有些判据只在异常页面才触发（岗位已关闭、提交成功、重复投递），
  拿正常岗位页核不动它们，但它们照样计入 `all_valid`。
  **修法**：`unprovable` 单列一栏，投递器在自己那行说明里写「不代表」。
  **钉住它的测试**：`test_unprovable_checks_are_surfaced`

### 13. 如果重来，方案里该提前写上哪句话

- **「这个功能的入口配好了吗」要写进 §2。** 这次代码全绿、
  `mcpServers` 是空的 —— 功能做完了一次没用上。§2 问「用户会看到什么」，
  而「用户看不到，因为客户端不知道它存在」是这一栏该拦住的事。
- **「只有 X 过边界」这句话，断言要放在交出去那一刻。** 放在下游的
  「有没有被用到」上，等于让约束靠一个巧合成立 ——
  而下游多读一个键就静默失效，失效的表现是身份数据出现在对话里。
- **守卫被自己的合理用例误伤时，别放松守卫，去改判据的粒度。**
  `list_sync_runs` 那次如果按「加个例外」处理，
  下一个 `sync_xxx` 就会顺着例外进来。
- **数不出全集的东西只能用白名单。** `f"apply_{status}"` 拼出来的 kind
  grep 不出来，黑名单必漏。这条已经进了模板级的教训
  （和 plan 013 的 `EXPECTED_SHAPE` 是同一条）。
- **「全部有效」之前先问一句：这次能证明的和不能证明的分开了吗。**
  `unprovable` 那一栏不列出来，一个绿灯就把「没验过」洗成了「验过是好的」。
