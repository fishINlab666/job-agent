## 一、产品设计

### 1. 为什么现在做

现在的 `GRAD_WINDOW = {"campus": "26", "intern": "27"}`（`jobagent/adapters/tencent_join.py:44`）把 6 种招聘标签压成 2 个桶，再给每个桶配一个**单一届别**。这个形状和站点的实际语义不符，有两处错：

**错一：实习岗被标成「27 届」，实际上是「在读即可」。** 站点原文（`V2Post_zh-cn.js`，§9 命令 B）：

```
实习生 · 毕业时间：2025年9月1日-2026年12月31日；
        此入口也可投递其他面向在校生的实习机会（不限毕业时间）
```

`日常实习`（198 条）、`实习生 青云计划`（790 条）、`Pre留学生实习`（42 条）招的是**在读学生**，大二大三都能投。标成 `"27"` 的后果：一个 28 届（现在大二大三）的用户，`classify` 判「届别 27 不在 ['28']」，805 条腾讯岗位全军覆没。实测现状 `[28]` 画像 hit = **0**（§9 命令 D）。

**错二：`应届实习`（279 条）和 `实习生 青云计划` 挤在同一个 `intern` 桶里，但它们不是同一拨人。** `应届实习` 是应届生的实习（和应届生招聘同一届），`日常实习` 是在读实习。现在两者拿同一个届别值。

不做的后果：**在读学生（非当届）在腾讯一条岗位都看不到。** 这不是「字段有点旧」，是整个源对这类用户不可见。

顺带修掉一处定义违背：`docs/kb/job-fields.md:41` 写「这一列的定义是**源站结构化字段里的届别**」，而腾讯的 `grad_year` 是推的 —— `searchPosition` 的 13 个字段里没有任何毕业窗口（§9 命令 A）。本方案把这一列的来源从「猜一个窗口」改成「按站点自己的入口语义推」，并在 §8 说明为什么不干脆存 `NULL`。

### 2. 用户会看到什么

场景一，一个 26 届（当届）用户：

```
profile.yaml 里 grad_years: ["26"]
  → uv run jobagent sync tencent_join
  → uv run jobagent jobs --matched
  → 屏幕上从 10 条变成 41 条
```

变多的 31 条是实习岗 —— 26 届当然可以投在读实习，之前被「届别 27 不在 ['26']」挡掉了。

场景二，一个 28 届（现在大二大三）用户：

```
profile.yaml 里 grad_years: ["28"]
  → 同上两条命令
  → 屏幕上从 0 条变成 17 条
```

这 17 条全是日常实习/青云实习/Pre留学生实习。**应届岗仍然看不到，这是对的** —— 大二学生投不了 2026 届应届生招聘。

场景三，现在的真画像（`["26","27"]`）用户**看不到任何变化**，41 条还是 41 条。这一点写进 §7，不拿它当收益。

### 4. 数据长什么样，空值怎么办

| 字段 | 有值时 | 取不到时 | 「没有值」和「不匹配」分开了吗 |
|---|---|---|---|
| 应届类标签（`应届毕业生*` / `应届实习`）→ `grad_year` | `"26"`（站点入口届别，模块常量） | —— | —— |
| 在读实习类（`实习生 青云计划` / `日常实习` / `Pre留学生实习`）→ `grad_year` | `"不限"` | —— | —— |
| 认不出的标签 → `grad_year` | —— | `None` → 落库 `NULL` | 是。`match.py:104` 的 `parse_grad_years(None)` 返回 `None` → 判 `unknown` 不判 `miss` |
| `jobs.grad_year` | `"26"` 或 `"不限"` | `NULL`（**不写空串**） | 是 |
| `parse_grad_years` 三态 | `["26"]` / `[]`（不限） | `None` | 是，三态已有，本方案不动它 |

四条必须守住的：

1. **在读实习存 `"不限"`，不存 `None`。** 这两个是不同的状态：`"不限"` → `parse_grad_years` 返回 `[]` → `match.py:114-115` 判**命中**；`None` → 判 `unknown`，用户要靠 `--allow-missing` 才看得到，且带「?」标记。站点明说了不限毕业时间，那是「知道不限」不是「不知道」。§9 命令 F 验过这两态的落点。
2. **应届类存 `"26"`，跟站点入口走，不跟当前年份算。** 不许写成 `str(date.today().year % 100)` 之类的自动推导 —— 站点开哪一届是站点的事，2026-08 挂的就是 26 届（这正是上一版判断错的地方）。
3. **认不出的标签落 `NULL`，不许兜底。** `tests/test_adapter_tencent.py:121-133` 的 `test_unknown_type_grad_year_none` 已经在钉这个。
4. **分桶必须按 `recruitLabelName` 原文，不能按 `recruit_type`。** 理由见 §6。

### 5. 硬约束在哪一行

本方案没有不可撤销后果，**全是软约束**：改的是一个推导常量的形状，写库走 `sync` 的常规 UPDATE 路径，跑错了改回来再跑一轮。不涉及代投、删除、外发。

唯一要点出的：**这个改动在存量 805 条上不生效** —— `grad_year` 不在指纹里，`sync` 会走「只更新 `last_seen_at`」的分支。所以落地顺序是硬的：**007 改推导 → 008 的 `refresh-grad-year --apply` 刷存量。** 单做 007 会看到「改了代码、`sync` 说 `updated=0`、库里没动」，白排查一次。

### 6. 判据的粒度

判据链现在是三级，本方案把最后一级的**输入**从第二级换到第一级：

```
现在：recruitLabelName（6 种）→ _recruit_type（2 桶）→ GRAD_WINDOW → 届别
本方案：recruitLabelName（6 种）→ 届别语义（2 类，但边界和 recruit_type 不同）
```

**必须按 `recruitLabelName` 分，不能按 `recruit_type` 分。** 差这一级会命中什么（§9 命令 C 实测）：

| 标签 | 条数 | `recruit_type` | 本方案的届别 |
|---|---|---|---|
| 应届毕业生 青云计划 | 849 | campus | `"26"` |
| 应届毕业生 | 237 | campus | `"26"` |
| **应届实习** | **279** | **intern** | **`"26"`** ← 和 `recruit_type` 不同边界 |
| 实习生 青云计划 | 790 | intern | `"不限"` |
| 日常实习 | 198 | intern | `"不限"` |
| Pre留学生实习 | 42 | intern | `"不限"` |

`应届实习` 是分界线：它的 `recruit_type` 是 `intern`，但届别语义跟着应届走。**按 `recruit_type` 分桶就无法表达这一行** —— 这是现在这个 bug 的根。

`_recruit_type` 本身的两桶划分（campus / intern）**不改** —— 它表达的是「岗位性质」，那个分法是对的，只是不能拿来当届别判据。

### 7. 数字的口径

| 这个数 | 分子数的是什么 | 分母数的是什么 | 会不会随时间动 |
|---|---|---|---|
| 「`[26]` 10 → 41」 | 画像 `grad_years=['26']` 时判 hit 的腾讯开放岗位数，改前 / 改后 | 805 条腾讯开放岗位 | **会。** 随画像、随库里开放岗位数、随源站上下架 |
| 「`[28]` 0 → 17」 | 同上，画像 `['28']` | 同上 | 会 |
| 「`[27]` 31 → 17」 | 同上，画像 `['27']` | 同上 | 会 |
| 「真画像 41 → 41」 | 真 `profile.yaml`（`["26","27"]`）下的 hit 数 | 同上 | 会 |
| 新届别分布 `不限 346 / 26 459` | 按新语义推导后的分组计数 | 805 条腾讯开放岗位 | 会 |

四条口径警告：

- **`[27]` 那一档是 31 → 17，往下走。** 这是**正确的下降**：27 届（明年毕业）现在投不了 2026 届应届生招聘。别把它当回归。
- **真画像 41 → 41 不代表本方案无收益。** 收益在 `[26]` 和 `[28]` 两档，真画像同时要 26/27 所以被掩盖。
- **`346` 和 `459` 的和是 805，不是 807。** 807 是全表（含 2 条 `closed_at` 非空），805 是开放岗位。
- **这些数会动，报的时候带日期和画像。** 全部是 2026-08-09 快照，最后一轮 sync 是 2026-08-06T17:07。不要把 `41` / `17` 写进任何文档当常量。

### 8. 这次明确不做什么

- **不用 bundle 里那两个日期窗口做判据。** **已推翻（2026-08-09）**：命令 B 只在语言包定义文件里数引用，实际在 `renderProjectMeta` 里各被引用 2 次，是真在渲染的声明。但站点对 `应届实习`(pid=2) 返回 null，届别是我按标签推断的。
- **不改「2026 届」这个入口届别的值，也不做自动年份推导。** 站点开哪一届是站点的事。换季由 008 的告警 + 刷新命令承载。写成 `date.today()` 推导会在 2026-08 得出 27 —— 正是上一版判断错的方向。
- **不干脆存 `NULL`（方案 D 的一半）。** `NULL` 是「不知道」，而站点明说了实习入口「不限毕业时间」、应届入口是 2026 届 —— 我们**知道**。存 `NULL` 会让 805 条全部判 `unknown`，用户得靠 `--allow-missing grad_year` 才看得到，且全带「?」标记：把一个已知事实降级成信息缺失。代价是要在 `docs/kb/job-fields.md` 里说明这一列对腾讯是「按入口语义推的」而非「源站字段抓的」，那一句照写。
- **不修 `_recruit_type` 的两桶划分。** 它表达岗位性质，分法是对的（§6）。本方案只是不再拿它当届别判据。
- **不把 `grad_year` 加进 `_fp()`。** 实测加一个键改全部 9401 行指纹，造 9401 条空 diff 假事件，是 006 问题 1 同型放大 588 倍。理由和替代方案在 008 §8。
- **不解决换季**（问题 5）。那是 008。007 落地后必须跑 008 的刷新命令，见 §5。
- **不动飞书适配器的 `grad_year=None`。** 那是「源站真的没有」，被 `tests/test_adapter_feishu.py:271` 钉住。
- **观察项，不在本方案内**：`实习生 青云计划`（268 条）是否真的「在读即可」，以及 `应届实习`（93 条）是否真的跟当届走 —— 两条都是 §3 里标了「推理，未实测」的假设。前者若错是**误报**方向（268 条对非当届用户放宽成可投），比后者严重。**已核实（2026-08-09，renderProjectMeta）**：青云实习（projectId=20）在站点分派表里属实习桶，带「不限毕业时间」tip，是站点声明而非推理。应届实习（projectId=2）站点返回 null，届别是我按标签推断的。

### 10. 测试钉的是哪几条

| 结论 | 测试 | 做一半会红的那条 |
|---|---|---|
| 应届类标签（含 `应届实习`）拿入口届别 | `test_adapter_tencent.py::TestGradYear::test_campus_labels_get_entry_year` —— 三个应届标签，断言 `parse_grad_years(gy) == ['26']` | 只改了 `应届毕业生` 没改 `应届实习` 时红。**这是本方案的分界线**，必须单独有断言 |

| 认不出的标签届别是 `None`，不兜底 | `test_unknown_type_grad_year_none`（**已存在**，`tests/test_adapter_tencent.py:121-133`） | 加 `.get(x, "26")` 兜底时红 |

三条关于「测试必须能被变异证伪」的：

1. **断言要过 `parse_grad_years`，不要断言字符串字面量。** 写 `gy == "不限"` 是钉拼写；写 `parse_grad_years(gy) == []` 是钉语义 —— 后者在有人改成 `"不限届别"`（等价）时仍绿，在改成 `"在读"`（落 `None`）时红。**要钉语义。**
2. **在读实习那条必须断言 `== []`，不能只断言 `is not None`。** `["27"]` 也满足 `is not None`，那个判据放过了整个 bug。
3. `tests/test_ingest.py:62` 的 `make_job()` 把 `grad_year` 写死 `"27"`，20 多条 ingest 测试共用，**现在没有一条测试让它变过**。上表最后一条要先给 `make_job` 加可变 `grad_year` 参数。
