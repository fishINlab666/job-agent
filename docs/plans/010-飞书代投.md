## 一、产品设计

### 1. 为什么现在做

**不做的后果分两层。**

第一层，现在就在发生：飞书四家 8594 条岗位的 `apply_url` 全是死链。
`apply_url` 的唯一用途是「点开就是官网那一页」拿去人工核对（`kb/job-fields.md`），
而用户点开看到的是「您正在寻找的页面不存在」。**匹配结果没法核对，整条筛选链的
产出等于不可信** —— 用户拿到一份推荐列表，一个都点不开。

第二层是代投：飞书是本项目岗位量最大的源（8594 / 9399 = 91%），
腾讯只有 805 条。代投只支持腾讯的话，91% 的岗位池里一个都投不了。

**为什么这个错能活到现在没被发现。** `_position_url()` 的 docstring 自己写了
（`feishu.py:246-250`）：「这些页面是客户端渲染的 SPA，任何 id（含乱填的）都回同一个
200 外壳，所以 200 只证明路由存在……要验它得跑真浏览器看 network」。
当初的验证只到 HTTP 状态码，而 SPA 的 404 是**渲染层**的 —— HTTP 照样 200，
body 209KB。上一份方案把这个缺口写下来了，但没人去跑那个浏览器检查。
这次跑了，答案是形状错的。

### 2. 用户会看到什么

修链接之后（现在就能感知的部分）：

```
用户跑 jobs --matched 拿到推荐列表 → 点 apply_url
  → 屏幕上出现那个岗位的正文（职位描述、职位要求、城市、招聘项目）
  而不是「您正在寻找的页面不存在 请检查网址是否正确」
```

代投（本方案后半）：

```
用户: apply <job_id>
  → 屏幕上出现：打开了岗位页 / 检测到未登录
  → 「需要登录。请先用 --no-headless 手动登录一次，再重新 prepare」
  （四个租户的登录都是手机号 + 验证码，必须人来做）

用户手动登录过一次之后，再 apply <job_id>
  → 屏幕上逐字段列出：姓名 ← identity.name = 张三
                      手机号 ← identity.phone = 138****8000
                      ...
  → 「以上内容将提交到 <公司>。确认投递？」**停在这里，不提交**
  → 用户确认 → 才点提交 → 「投递成功」或「源站提示已投递过」
```

## 二、具体实现

### 4. 数据长什么样，空值怎么办

修 URL 那半：

| 字段 | 有值时 | 取不到时 | 「没有值」和「不匹配」分开了吗 |
|---|---|---|---|
| `apply_url`（新形状）| `https://<host>/<portal>/position/<id>/detail` | 不会取不到：`post_id` 是构造前提，没有 id 的岗位在 `fetch()` 里已经被 `skipped_no_id` 挡掉 | 是 |
| `portal` | 门户段，如 `campus` / `edu` | 退到 `index`（已有行为，不改）| 是 |
| 存量修复的 `apply_url` | 新形状 | 老形状已经是死链，**修不出来的行保留原值并报出来**，不写 `NULL` | 是 —— 照 `refresh_grad_year` 的第三条硬约束 |

代投那半：

| 字段 | 有值时 | 取不到时 | 「没有值」和「不匹配」分开了吗 |
|---|---|---|---|
| `tenant` | 从 `source_key` 第二段解析，如 `feishu:nio:campus` → `nio` | `source_key` 段数不对就抛错，**不猜** | 是。猜租户名是这个项目复发三次的错法 |
| `portal` | `source_key` 第三段 | 缺第三段退 `index`，和适配器一致 | 是 |
| `confirm_token` | 16 位随机串 | **blocked 时显式空串 `""` 并且不注册会话** | 是 —— 空串是非 NULL，但这里不入库，只作「没 token 就调不动 execute」的信号（`CLAUDE.md` 记的第二个坑）|
| 表单字段值 | 画像里的值 | `None` → 标 `action="skip"` + note 说明，不静默漏 | 是（复用 `TencentJoinSubmitter._plan_fields` 的形状）|

### 5. 硬约束在哪一行

代投是不可逆动作，用**硬约束**，且不新发明机制 —— 直接复用 `submitters/base.py`：

- `FeishuSubmitter` 上**没有 `submit()` 方法**。想提交只有 `prepare` → 人工确认 → `execute(token)`。
- `prepare()` 返回 blocked 时 `confirm_token=""` 且不进 `SESSIONS`，`execute` 拿不到有效 token。
- `execute()` 先把页面上的值读回来重算 `digest`，和确认时不一致就拒绝提交。

修 URL 那半也有一条硬约束，方向不同（防的是假信号不是不可逆动作）：
**存量修复只写 `apply_url` 一列，不碰 `fingerprint`、不碰 `last_seen_at`。**
理由见 §7。

### 6. 判据的粒度

两处判据，都要写清是哪一级：

1. **「这条 URL 需要修吗」的判据**：`apply_url NOT LIKE '%/detail'`，
   粒度是**单行**，不是「按 source_key 整批」。差一级的后果：按 source_key 判会把
   已经修好的行再拼一次 `/detail`，变成 `/detail/detail`。所以必须逐行判、且幂等。

2. **「这个岗位归哪个租户」的判据**：`source_key` 的**第二段**（`feishu:nio:campus` → `nio`），
   粒度是**租户级**，不是品牌级。差一级的后果就是 `ats.py` 那个原型错法的重演 ——
   拿 `feishu.cn` 当判据会把所有飞书租户混成一家，投到错公司去。
   **域名 slug 不是归属判据**（`kb/company-portals.md` 文末），但 `source_key` 是我们自己
   写进去的、已经用页面标题核实过归属的，可以信。

### 7. 数字的口径

| 这个数 | 分子数的是什么 | 分母数的是什么 | 会不会随时间动 |
|---|---|---|---|
| 死链 8594 / 8594 | `apply_url NOT LIKE '%/detail'` 的行数 | `source_key LIKE 'feishu%'` 的全部行（含已关闭）| **会** —— 岗位池是活的。这个数是 2026-08-10 的快照 |
| 修复条数 | 实际执行 UPDATE 的行数 | 同上 | 会。**幂等：跑第二次报 0** |
| 飞书占比 91% | 8594 | 9399（五家合计）| 会，见 `kb/company-portals.md` 的重测漂移那段 |

**为什么修 URL 不能顺手重算指纹。** `apply_url` 在 `_fp()` 里（`ingest.py:61`），
也在 diff 键里（`ingest.py:326`）。如果走正常 `sync` 路径修，8594 行的指纹全变，
造出 **8594 条 `job_updated` 事件**，每条 diff 都是 `apply_url: 老形状 → 新形状`。
那是**噪声不是信号**：用户订阅「岗位有变化」是想知道岗位本身变了，
不是想知道我们修了个 bug。

这和 `refresh_grad_year` 是同一个形状的问题（`ingest.py:90-92` 记着
「顺手重算指纹会造出 9401 条 diff 为空的假 job_updated —— 那是 plan 006 问题 1 的同型放大」），
所以修法也照抄那三条硬约束：只写一列、幂等、有值不许被静默改成 NULL。

### 8. 这次明确不做什么

- **不做飞书的表单填写和真提交**，因为**现在做等于编**。四个租户的表单长什么样
  必须登录后才看得见，而登录是手机号验证码、只有用户本人能做。
  没看见表单就写 `FORM_FIELDS`，写出来的选择器是猜的 —— 而「猜命名空间」
  是这个项目复发三次的错法。本轮 `FeishuSubmitter` 做到**「打开岗位页 → 判岗位是否关闭
  → 判登录门 → blocked 并告诉用户去登录」**为止，把 §3 那四条假设留给下一轮。
  这一步不是残废功能：它已经能替用户判掉「岗位关了」和「没登录」，
  而且把两阶段骨架和拒绝路径全部钉住了。

- **不做「自动登录」**，因为手机号验证码是有意的人机验证，绕它等于对抗风控。

- **不改 `_fp()` 的键**，因为指纹口径变一次全库重算，代价和收益不匹配。
  `apply_url` 留在指纹里是对的 —— 源站真改了链接形状就该报变化。

- **不动腾讯那半**（`TencentJoinSubmitter`），因为它的登录门问题是同一形状但已经修过，
  这次不碰它免得引入回归。

- **不追 `job_process_id` / `code` 这些新看到的字段**，因为当前没有用途。
  探测顺手看到不等于该采（`kb/job-fields.md` 的 `raw_category` 就是这条的先例：只落原文、不参与判定）。

### 12. 实现中踩到的坑

- **现象**：库里 8594 条飞书 `apply_url` 全部打不开，页面显示「您正在寻找的页面不存在」。
  **原因**：真实详情页形状是 `/{portal}/position/{id}/detail`，代码少了 `/detail`。
  **为什么活到现在没被发现**：这些页面是客户端渲染的 SPA，**404 发生在渲染层，
  HTTP 照样 200 而且 body 有 200KB**（实测 nio 209298 字节）。当初的验证只到状态码。
  更值得记的是：`_position_url()` 的 docstring **当初就把这个缺口准确地写下来了**
  （「200 只证明路由存在……要验它得跑真浏览器看 network」），但没人去跑。
  **修法**：`_position_url()` 加 `/detail`；存量走 `repair_apply_url()` 单列原地改。
  **钉住它的测试**：`test_detail_suffix_always_present`、
  `test_missing_judged_by_body_not_status_code`（守判据不许退回状态码）。

- **现象**：`apply_url` 一改，全库指纹都会变。
  **原因**：`apply_url` 在 `_fp()` 里（`ingest.py:61`）也在 diff 键里（:326），
  走 `sync` 会造出 8594 条 `job_updated`，每条 diff 都是「我们修了个 bug」。
  **修法**：仿 `refresh_grad_year` 写 `repair_apply_url()`，只写一列、幂等、
  形状不认识的保留原值。**和 `refresh_grad_year` 是镜像关系**，值得并排记：
  一个是字段不在指纹里所以 sync 不修，一个是字段在指纹里所以 sync 会修但会造假事件
  —— 方向相反，结论一样（单列原地改，不碰指纹）。
  **钉住它的测试**：`test_does_not_touch_fingerprint`、`test_emits_no_events`、
  `test_idempotent_no_double_detail`。

- **现象**：`test_no_apply_button_blocks` 断言失败，走到了登录门那条分支。
  **原因**：我写的是 `page.locator(sel).first.count()` —— `count()` 该问 locator
  本身，`.first` 是「第 0 个元素」这个概念，对它数个数语义上就是错的。
  真实 Playwright 下恒为 0/1 掩盖得住，假页面下直接暴露。
  **修法**：`apply_loc.count()` 判存在，`apply_loc.first.click()` 才点。
  **钉住它的测试**：`test_no_apply_button_blocks`。

- **现象**：`test_replay_refuses` 报 DID NOT RAISE。
  **原因**：我按「重放会抛 TokenError」写的，实际 `execute` 把 `TokenError` 收在
  里面转成 `blocked` + `note=token_consumed`，只有「压根没这个 token」那条才抛。
  这是**我对已有契约的误解，不是代码的问题**。
  **修法**：改测试断言，并在 docstring 里写清这个区别，免得下一个人再猜。

### 13. 如果重来，方案里该提前写上哪句话

**「对 SPA，HTTP 200 不是页面存在的证据 —— 判据必须是渲染后的正文。」**

但更值得改的是模板，而不是多写一句话。`_position_url()` 的 docstring 已经把这个
缺口写得很准确了，然后它在那儿躺了四天没人管。**「方案里写清没验什么」只是第一步，
得有人把它排进待办**，否则那段话只是免责声明。

所以模板 §3 的「打算怎么验」那一栏，填的不该是「以后跑浏览器看」这种意向，
而该是**一条能跑的命令 + 一个待办项**。这条和 §0 是同一个道理：
方案里所有「将来要做」的东西，都得有一个地方记着它还没做。

本方案自己也留了同型的四条假设（§3 下半：登录后是不是站内表单、登录态能不能
持久化、四租户表单是否一致、有没有简历上传）。它们都卡在同一个前置条件上
——**必须有人真登录一次**。按上面这条要求，它们不该只写在这儿，
所以已经落成了代码里一个看得见的形状：`FORM_FIELDS` 是空的，
`prepare` 走到表单会 blocked 并存一张 `form_*.png` 说「按它补 FORM_FIELDS」。
下一轮的入口就是那张截图，不是这段文字。
