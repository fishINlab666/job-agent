## 一、产品设计

### 1. 为什么现在做

不做的后果不是「少一个字段」，是**主库里 1911 个已经确认命中的岗位用户看不到**。

主库 9399 条开放岗位，严格匹配只出 41 条，全是腾讯。飞书四家（字节 7368、蔚来 634、
小鹏 431、商汤 161）贡献 **0 条**。原因不是它们不匹配——这 1911 条的岗位族、招聘类型、
城市三项**都已经确认命中画像**，唯一缺的是届别，而届别在飞书的结构化字段里根本不存在
（四租户 × 12 门户全量核实过，见 003）。

现在唯一的绕法是 `--loose`，但它是一个粗开关：一按下去，届别、岗位族、招聘类型、城市
四个维度同时放开，结果 2533 条里混进 581 条连岗位族都判不出的。用户要么看 41 条，
要么看 2533 条里自己捞，没有中间档。

### 2. 用户会看到什么

```
用户敲 jobs --matched              → 只给确定命中的        → 95 条（改动前 41，全腾讯）
用户敲 jobs --matched
     --allow-missing grad_year     → 放开「届别没写」这一维 → 1952 条，族/类型/城市都已确认
用户敲 jobs --matched --loose      → 四个维度全放开        → 2533 条，含 581 条族判不出
```

后两档的条数**改动前后没变**（1952 / 2533），只有第一档从 41 涨到 95。这正是标题通道
应有的形状：它把 54 条从「信息不全」搬进「确定命中」，没有扩大岗位池，也没造出新的 miss。
如果第三档跟着涨了，说明标题解析在往池子里加东西；如果跌了，说明它在错杀。

这两个不变量不是「测出来正好没动」，是**算术上必然**，所以它们能当断言用：

```
第二档 = hit + 只差届别桶        关: 41 + 1911 = 1952    开: 95 + 1857 = 1952
第三档 = hit + 全部 unknown      关: 41 + 2492 = 2533    开: 95 + 2438 = 2533
```

标题通道做的事只是把行从「只差届别桶」搬进 hit，而这两个桶**都在这两档里面**，搬多少
都不影响档内总数。于是可以反过来立三条断言（`uv run` 见 §9 命令 A、E）：

| 必须不变 | 实测 | 一旦变了说明什么 |
|---|---|---|
| 第二档 1952、第三档 2533 | 都没变 | 涨 = 标题解析在往池子里加东西；跌 = 在错杀 |
| miss 6866 | 没变 | 涨 = 标题解出的届别和画像不合，把本该 unknown 的判死了 |
| unknown 里「含岗位族未知」581 | 没变（2438 里 581，2492 里也是 581）| 变了 = 这条通道漏到了届别以外的维度上 |

第三行是最容易忘的一条：改届别不该动族。它确实没动——族未知从 581 到 581，动的只是这
581 条里有多少条**同时**还缺届别（581 → 478，另外 103 条只剩族这一维）。

第二行是这次新增的档位。它和第三行的区别是：第二行里的每一条，除了届别之外**所有维度
都是确认命中的**；第三行里有 581 条是「连是不是运营岗都不知道」。这两种「不确定」不该
共用一个开关。

另外小鹏有 54 条岗位标题里明写了「【27届校招】」，这批人在第一行就该出现，不该等到
用户放开届别才看见——标题上写着的东西不算「没写」。

## 二、具体实现

### 4. 数据长什么样，空值怎么办

| 字段 | 有值时 | 取不到时 | 「没有值」和「不匹配」分开了吗 |
|---|---|---|---|
| `jobs.grad_year`（库列） | 源站结构化字段原文：`"26"`、`"2026-2027年毕业"` | `None`，**不写 `""`** | 是 —— 下游 `parse_grad_years` 三态 |
| `parse_grad_years()` | `["26","27"]` 明确集合 | `None` 看不懂 / `[]` 明确写了不限 | 是 —— `match.py:95-100` 分三支 |
| `grad_years_from_title()`（新增） | `["27"]` | `None` | 是 —— **永不返回 `[]`**，理由见下 |
| `Verdict.missing`（新增） | `("grad_year",)` 机读键 | `()` | 是 —— 和人读的 `unknowns` 并存，各管一头 |
| `filter_jobs(allow_missing=)`（新增） | `frozenset({"grad_year"})` | `None` | 是 —— `None` 与 `frozenset()` 同义（都严格），不制造第三种含义 |

两条关键取舍：

**`grad_years_from_title()` 永不返回 `[]`。** 标题里出现「不限 / 所有 / 任意 / 全部 / any」
的概率远高于它真表示「届别不限」——实测撞上的是 `Anyscale 平台研发`、`全部业务线-数据分析`、
`任意方向-算法`。返回 `[]` 的语义是「任何届别都命中」，等于把「不知道」洗成「确定命中」，
方向是错的。标题这条通道只允许两种结果：明确的届别集合，或者 `None`。

**标题解析出的届别不写回 `jobs.grad_year`。** 那一列的定义是「源站结构化字段里的届别」，
`run_five.py` 的 `KNOWN_EMPTY["feishu"]["grad_year"]` 和所有填充率都按这个定义在算。
把标题结果混进去，那句「结构化字段里没有届别」就变成假的，而且下次量填充率会量出一个
混了两条通道的数，说不清分子是什么。标题是另一条观测通道，**判定时读，不落库**。

### 5. 硬约束在哪一行

这次改的是读、筛、显示，错了顶多多看或少看几条，可撤销，所以主体是软约束。两处例外：

- **硬约束：不给 adapter 增加任何 `grad_year` 赋值路径。**
  `tests/test_adapter_feishu.py:271` 的 `test_grad_year_always_none` 已经把它钉成 API 形状——
  飞书适配器返回的 `grad_year` 必须是 `None`。这次不碰这个测试，它就是「顺手编一个」的闸门。
- **硬约束（既存）：`--allow-missing` 到不了代投。**
  `match` 只被 `cli.py` 和两个测试 import，`jobagent/submitters/` 里一个都没有（核实见 §9 命令 D）。
  所以放宽的是「看什么」，结构上流不到「投什么」；代投的闸门仍是 001 的 `confirm_token`。

### 6. 判据的粒度

这次要认的是「标题里这个数字是不是毕业届别」。判据取**「届」字级**，不是**年份级**。

差一级命中什么，实测（§9 命令 B）：

- 「届」字级：348 条，全部解析成 `['27']`，无误判。
- 年份级（直接把标题喂给 `parse_grad_years`）：多出 4 条，**4 条全错** ——
  2 条 `Any-to-Any` 被判「不限届别」（等于任何届别都命中），2 条「2026年校园大使」的 2026 大概是活动年份。

裸年份在标题里是歧义的：可能是招聘年度（「2026年秋季校园招聘」）、活动届次（「2026年校园大使」）、
毕业届别（「2026届」）。结构化的届别字段里没有这个歧义——字段名已经把语义定死了。
所以同一个 `parse_grad_years` 不能在两条通道上用同一套宽松度。

### 7. 数字的口径

| 这个数 | 分子数的是什么 | 分母数的是什么 | 会不会随时间动 |
|---|---|---|---|
| 「只差届别 1911 条」 | `classify` 判 unknown 且 `missing == ("grad_year",)` 的行 | 主库 `closed_at IS NULL` 的 9399 条 | 会。岗位池每次 sync 都动，画像一改也动。报数必须带日期和画像 |
| 「标题补回 54 条」 | 加了标题回退后从 unknown 变 hit 的行 | 同上 9399 | 会，而且**强依赖公司**：小鹏 54、字节 0。不许合成一个全库百分比往外报 |
| 「标题解掉了 348 条的届别」 | 标题能解析出届别的开放岗位行 | 同上 9399 | 会。**这个数比 54 大**，因为解掉届别 ≠ 升成 hit：其中 54 条四维齐全，103 条岗位族仍判不出，其余在族/类型/城市上是确定不命中。报「标题的产出」时说清是哪一个 |
| 「届别填充率」 | `grad_year IS NOT NULL` 的行 | 按 `source_key` 分组的开放行数 | 会。**必须按源分组**，理由见下 |
| 「严格命中 41 条」 | `classify` 判 hit 的行 | 同上 9399 | 会。这 41 条全是腾讯，且靠的是推断出来的届别 |

届别填充率必须按 `source_key` 分组报，不许合并：腾讯 805 条是 100%，但那是
`GRAD_WINDOW` 推出来的，不是抓到的；飞书 8594 条是 0%，是字段真的不存在。
合起来报「全库 8.6%」会同时盖掉两件事——腾讯那份是推的，飞书那份是缺的。

### 8. 这次明确不做什么

- **不给飞书按 `recruit_type` 推届别**，因为现在做等于编数据。这不只是「不合规矩」，
  是**已经被自己的数据证伪**：小鹏校招门户上 27 届 343 条和 26 届 2 条并存，
  「一个校招门户 = 一个届别」不成立。和「岗位族判不出写 `None` 不兜底 `other`」、
  「`recruit_type` 认不出不兜底 `social`」是同一条原则。
- **不改腾讯的 `GRAD_WINDOW`**，即使 §3 已经把它标成可疑。改它等于改一个已落库源的判据，
  影响 805 条里的 366 条，而且「把 `campus` 从 `"26"` 改成 `"27"`」只是换一个猜的值，
  同一类错再犯一次。要动它得先去门户上看页面写的是哪一届 —— 那是下一份方案。
- **不把标题解析结果写回 `jobs.grad_year`**，理由见 §4。
- **不在 `jobs` 表加届别展示列**。这次届别的用法是「不挡路」，不是「要看」；
  真要看的时候 `--allow-missing` 那一档里带 `?` 的行会把原因打出来。
- **不动 `--loose` 的行为**。它继续等于「四维全放开」，老用法不变，新档位是加出来的。

| 标题写「24届」→ 判 miss，不是 hit（**反向用例**） | `test_title_grad_year_can_cause_miss` | 只接了「命中」分支，漏了「不合」分支 |
| `missing` 键稳定，改人读文案不影响过滤 | `test_missing_keys_are_stable` | 只改了 `unknowns` 文案，`missing` 忘了加 |
| `allow_missing={"grad_year"}` 放届别、不放岗位族 | `test_allow_missing_is_per_dimension` | `allow_missing` 被当成布尔用，一放全放 |
| `--loose` 仍然等于全放开 | `test_loose_still_allows_everything` | 换成 `allow_missing` 时把老行为改坏 |
| 标题届别不落库（**归属用例**） | 既存 `test_grad_year_always_none` | 顺手在 adapter 里也填一份 → 两份真相 |
| 放宽后仍不把 unknown 当确定命中 | 既存 `test_unknown_is_not_a_confident_hit` | —— |

「做一半」在这次改动里的具体形状是：`Verdict` 加了 `missing`，但 `filter_jobs` 还在读
布尔 `include_unknown`。这种半成品下常见路径（严格、`--loose`）照样全绿，只有新档位是空的 ——
所以 `test_allow_missing_is_per_dimension` 必须断言「进来了哪些、挡住了哪些」，不能只断言条数。

### 12. 实现中踩到的坑

- **现象**：`Anyscale 平台研发`、`全部业务线-数据分析`、`任意方向-算法` 被 `parse_grad_years`
  判成 `[]`，也就是「不限届别 = 任何届别都命中」。
  **原因**：`_GRAD_UNLIMITED` 整个元组走子串匹配。中文词（「不限」「均可」）连写时必须按子串，
  但 ASCII 的 `"any"` 按子串就会撞上任何含 any 的英文词。**方向性错误**：把「不知道」洗成
  「确定命中」，比漏推严重。
  **修法**：按字符集拆开。中文继续子串，ASCII 改走 `re.compile(r"\bany\b")`。
  一开始想给全部词加词边界，但 `\b不限\b` 在 `届别不限` 上不成立（CJK 之间没有词边界），
  会把既存行为改坏。
  **钉住它的测试**：`test_ascii_any_needs_word_boundary`（新，参数化 3 例）+ 既存
  `test_unlimited_is_empty_list_not_none`（4 例，防修过头）。两侧同时绿才算修对。
  **命令**：`uv run pytest tests/test_match.py -k "ascii_any_needs_word_boundary or unlimited_is_empty_list_not_none" -q`
  **没修干净的部分（有意留着）**：`\bany\b` 挡不住连字符——`Any-to-Any` 里的 `Any` 两侧
  都是词边界，`parse_grad_years('混元-原生多模态(Any-to-Any模型)预训练')` 现在仍然返回 `[]`。
  主库里这样的标题有 2 条，全是腾讯。它**够不着**，因为：标题通道有「届」字门（这 2 条
  `grad_years_from_title` 返回 `None`，已被 `test_title_never_returns_unlimited` 钉住，
  见 `tests/test_match.py:129`），而字段通道只有腾讯有非空 `grad_year`，值来自
  `GRAD_WINDOW` 的 `"26"/"27"`，不会是自由文本。所以这是**边界不是缺陷**，没有真实入口。
  不继续收紧正则的理由：再改一轮只能靠猜「以后会不会有源站往 `grad_year` 里写英文」，
  而现在没有这样的源；等真有了，那时候能拿到真实写法再改，比现在猜准。
  **复查命令**（新源站接进来后重跑，返回非 0 就说明有了真实入口）：
  ```bash
  uv run python -c "
  from pathlib import Path
  from jobagent import db
  from jobagent.normalize import parse_grad_years, grad_years_from_title
  rows=[dict(r) for r in db.connect(Path('data/jobagent.db')).execute(
      'SELECT source_key,title,grad_year FROM jobs WHERE closed_at IS NULL')]
  # 字段通道里被判成「不限」的非空值 —— 这才是真入口
  bad=[r for r in rows if r['grad_year'] and parse_grad_years(r['grad_year'])==[]
       and not any(w in str(r['grad_year']) for w in ('不限','均可','所有','任意','全部'))]
  print('字段通道假不限:', len(bad), bad[:5])
  # 标题里含 any 但被门挡住的（应当全部 None，数字只作参考）
  leak=[r for r in rows if parse_grad_years(r['title'] or '')==[]
        and grad_years_from_title(r['title'] or '') is not None]
  print('穿过「届」字门的假不限:', len(leak), leak[:5])
  "
  ```

- **现象**：`filter_jobs(rows, intent, allow_missing=None)` 的语义有两种自然读法——
  「没传就严格」和「没传就不限制」。
  **原因**：参数从布尔 `include_unknown` 换成集合时带进来的。布尔只有两态，集合多了
  `None` / `frozenset()` / 非空三种，中间那层含义是新造出来的。
  **修法**：显式规定 `None` 与 `frozenset()` 同义（都只给确定命中的），不制造第三种含义，
  并把这句写进 docstring。
  **钉住它的测试**：`test_none_and_empty_set_mean_the_same`。

- **现象**：`uv run python /tmp/m1.py` 报 `ModuleNotFoundError: No module named 'jobagent'`。
  **原因**：脚本模式下 `sys.path[0]` 是脚本所在目录（`/tmp`），不是项目根。
  `pyproject.toml` 里的 `pythonpath = ["."]` 只对 pytest 生效。
  **修法**：`PYTHONPATH=. uv run python ...`，或者干脆写成 `uv run python -c`。
  §9 的命令全部收敛成 `-c` 形式，顺带避免往仓库里留临时脚本。
  **钉住它的测试**：无（工具链问题，不是代码行为）。记在这儿是为了下次量数时不再卡一轮。
