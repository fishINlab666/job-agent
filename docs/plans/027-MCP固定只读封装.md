## 一、用户问题和本轮边界

### 1. 为什么现在做

代码里已经有五个可用的只读工具，但旧接入说明让客户端直接启动开发目录里的 Python，
并依赖代码默认推断数据库和画像位置。开发目录会继续变化，客户端还可能读到旧分支；
结果是“配置看起来没变，实际启动的工具版本却变了”。历史上这已经出现过：原开发目录
曾暴露六个工具，其中一个会接触登录态浏览器。

本轮只解决“如何稳定、安全地启动现有五个工具”，不增加产品能力。

### 2. 用户最终会感受到什么

```text
固定运行包 + 明确指定生产数据库和画像
        ↓
无论客户端从哪个目录启动，都只能看到同一版五个只读工具
        ↓
路径失效、文件被替换或画像权限过宽时，启动直接失败，不返回假空数据
```

### 3. 已核实与推测

| 类型 | 结论 |
|---|---|
| 已核实 | 当前主线注册表恰有五个只读工具，聚焦测试为 `95 passed` |
| 已核实 | 五个工具绑定生产数据库和画像后均能只读返回结果 |
| 已核实 | 当前客户端配置仍指向可变开发目录；该目录的旧代码曾包含危险第六工具 |
| 已核实 | 当前没有 `jobagent.mcp_server` 进程，今天的观察任务不依赖 MCP |
| 推测 | 五个工具是否足够好用，要等真实客户端接通后的使用反馈；因此本轮不猜第六个工具 |

### 4. 这次明确不做什么

- 不新增第六个工具，不改五个工具的业务语义。
- 不碰采集、调度、云端、投递或真实数据库内容。
- 不修改 Claude / Codex / 其他客户端配置，不启动 MCP 进程。
- 不复制真实数据库、画像或个人信息进仓库、构建产物和日志。
- 不新造远程服务、控制面、manifest 执行器或第二套 MCP 框架。

## 二、设计

### 5. 唯一启动合同

固定包仍通过本地 stdio 启动，不监听端口。启动命令必须显式提供：

```text
python -m jobagent.mcp_server --db <绝对数据库路径> --profile <绝对画像路径>
```

启动层在 `mcp.run()` 前一次性验证并冻结两个输入：

1. 路径必须是绝对路径、普通文件且不是符号链接；缺失时直接失败。
2. 数据库必须能以 SQLite `mode=ro` 打开并读取既有 schema；不能创建空库。
3. 画像必须只允许当前用户读写，不能有 group/world 权限；读取仍只通过
   `match.load_intent(path)`，姓名、手机、身份证等字段不传给工具。
4. 同一进程只允许配置一次；第二次改绑到别的库或画像直接失败。
5. 配置成功后 `_conn()` 和 `_intent()` 只使用被冻结的输入，不再读取开发目录默认值。

这里没有新建一个“包管理系统”。所谓固定包只是：从一个已审核提交在最终目录安装依赖，
再把该目录、数据库和画像的绝对路径写进客户端。固定目录内构建虚拟环境，不能先构建再移动，
避免解释器脚本仍指向旧路径。

### 6. 为什么不另造一份画像文件

单独导出 intent 看起来更安全，但同一用户运行的本机进程仍能读取原画像，复制一份文件
并没有形成操作系统隔离，反而引入“画像更新了、导出副本没更新”的第二真源。本轮保留
现有 `match.load_intent()` 单入口和白名单，增加的是显式路径、权限检查与不可改绑。

### 7. 失败与恢复

| 失败 | 对外表现 | 恢复方式 |
|---|---|---|
| 路径缺失、相对路径或符号链接 | MCP 不启动 | 修正固定配置后重新启动 |
| 画像权限不是仅用户可读写 | MCP 不启动 | 将画像权限收紧后重新启动 |
| 数据库不可读或 schema 不对 | MCP 不启动 | 修正数据库路径；不得创建空库顶替 |
| 客户端仍显示非五工具 | 激活验收失败 | 退出客户端并恢复为不加载 job-agent，不沿用该运行实例 |

失败路径不改数据库、不改画像内容，也不自动修改客户端配置。

## 三、实施顺序

### 8. TDD 步骤

1. 在 `tests/test_mcp_server.py` 添加 RED：
   - `main()` 缺 `--db` / `--profile` 时不进入 `mcp.run()`；
   - 相对路径、缺失文件、符号链接、宽权限画像被拒绝；
   - 正确绑定后，从任意工作目录调用仍使用指定数据库和画像；
   - 同一进程不能改绑；
   - 真实注册表仍精确为五个工具。
2. 在 `jobagent/mcp_server.py` 增加最小 `RuntimeBinding` 和参数解析；不改工具函数接口。
3. 更新 `docs/MCP_SETUP.md`：删除可变开发目录的一键配置，改为固定包模板和激活门禁。
4. 测试、只读自审、本地提交；到此仍不触碰真实客户端。

fail-closed；正确临时库/画像时注册表精确为五个工具。检查只使用临时文件，不读写生产库。

### 10. 激活前最后门禁（不在本轮执行）

- 固定包来自已审核提交，安装目录和 Python 路径不再移动。
- 生产数据库与画像 SHA / 文件类型 / 权限只读核验通过。
- 旧 `job-agent` 客户端项先退出后替换；不能并存两个同名或两个不同来源实例。
- 重启后从客户端运行时注册表看到且只看到五个工具。
- 在真实客户端只调一次 `list_sources` 与 `list_jobs`，确认没有写库、没有启动浏览器。
- 任何一项失败，退出客户端并停止加载 job-agent；不把“配置文件写了”当成接通成功。

## 四、复盘（实现完成后回填）

### 11. 方案与实现偏差

实现范围与方案一致。数据库实际历史表名是 `runs`，不是设计草稿里口语化写的
“sync runs”；RED 后第一次 GREEN 因把表名写成 `sync_runs` 出现 2 个失败，改为读取真实
schema 的 `runs` 后通过。没有为此迁移数据库或增加兼容表。

### 12. 实际测试与已知限制

聚焦测试 `105 passed`，全量 `1117 passed, 2 skipped`。注册表仍精确为五个只读工具；
启动绑定只增加进程启动前验证，不改变工具参数和返回值。

真实客户端尚未激活，生产画像权限也尚未修改。因此本候选证明的是“固定包代码和模板
可以进入发布复核”，不证明客户端已经连接。客户端好不好用、是否需要第六个工具仍是
未知项，必须由后续使用反馈决定。
